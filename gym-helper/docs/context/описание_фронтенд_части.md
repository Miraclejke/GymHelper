У меня есть учебный frontend-проект `GymHelper`. Это React/Vite-приложение, которое я готовлю под будущий независимый backend по лабораторным работам на NestJS.

Цель проекта:

- трекер тренировок
- трекер питания
- трекер отдыха и сна
- минимальная аутентификация с регистрацией
- подготовка frontend-части под backend, без сложной архитектуры

Текущий стек:

- React 18
- TypeScript
- Vite
- React Router DOM
- CSS без UI-библиотек
- Zustand больше не используется для хранения основных данных

Текущее состояние проекта:

- frontend уже переведен на простой API-слой
- пока реального backend нет, вместо него используется локальная mock-реализация через localStorage
- страницы работают по схеме:
  1. загрузить данные
  2. редактировать локальный черновик
  3. нажать "Сохранить"
- на страницах есть состояния:
  - loading
  - error
  - empty
  - ready
- есть минимальный auth UI:
  - login
  - register
  - logout
- есть защита маршрутов через ProtectedRoute
- используется BrowserRouter, а не HashRouter

Основные сущности домена:

- AuthUser
- PlanExercise
- WorkoutDay
- WorkoutExercise
- WorkoutSet
- NutritionDay
- MealEntry
- RestDay

Функциональные разделы приложения:

- Dashboard
  - показывает быстрые переходы
  - показывает статистику за последние 14 дней
- Plan
  - недельный план тренировок по дням недели
  - упражнения редактируются локально и сохраняются кнопкой
- Workout
  - тренировка на конкретную дату
  - упражнения и сеты
  - данные загружаются по дате
- Nutrition
  - приемы пищи на конкретную дату
  - КБЖУ
  - подсчет итогов
- Rest
  - запись сна и отдыха на конкретную дату
- Login/Register
  - учебные формы входа и регистрации

Архитектура данных:

- pages больше не работают напрямую с глобальным store
- для данных используется отдельный слой `src/api`
- сейчас это mock API
- позже его нужно заменить на настоящий backend API, почти не меняя страницы

Как сейчас работает auth:

- auth пока учебный и локальный
- данные пользователя и сессии лежат в localStorage через mockDb
- есть тестовый admin:
  - email: `admin@gymhelper.local`
  - password: `admin123`
- роли:
  - user
  - admin
- роуты защищены на frontend
- в будущем нужно подключить реальную backend-аутентификацию

Что уже подготовлено под backend:

- frontend не завязан на Zustand-store как на базу данных
- все страницы уже ориентированы на API-запросы
- есть явное сохранение по кнопке
- есть auth UI
- есть protected routes
- есть понятные доменные сущности
- есть базовые состояния для запросов
- проект не перегружен сложной архитектурой

Что важно для будущего backend:

- сейчас `src/api/*` — это слой-замена будущих HTTP-запросов
- когда появится backend, нужно будет заменить mock-логику на `fetch`/HTTP-клиент
- интерфейс страниц желательно оставить как есть
- основной паттерн должен остаться:
  - GET данные
  - локально редактировать
  - SAVE через POST/PUT/PATCH

Что НЕ реализовано как полноценный backend:

- настоящая серверная аутентификация
- настоящая БД
- реальные REST endpoint'ы
- GraphQL
- SSE
- роли на backend-уровне
- Swagger/OpenAPI
- server-side validation
- file upload

Ограничения и упрощения:

- проект сделан специально простым и учебным
- без сложного state management
- без autosave на сервер
- без сложного realtime
- без тяжелых абстракций
