# Отчет По Лабораторной Работе 7

## 1. Название лабораторной работы

`ЛР7. Добавление аутентификации и авторизации`

## 2. Цель лабораторной работы

Целью ЛР7 было:
- довести аутентификацию проекта до более полного состояния;
- реализовать разграничение прав между ролями `user` и `admin`;
- защитить backend-ресурсы через guard'ы;
- добавить сценарии управления учетной записью и административный сценарий.

## 3. Адаптация ЛР7 под проект GymHelper

Классическая формулировка ЛР7 предлагает внешний auth-провайдер. Для проекта `GymHelper` это было бы лишним, потому что:

- в проекте уже была рабочая session-based auth через `express-session`;
- React frontend уже был связан именно с этим backend;
- для учебной защиты важнее было показать аутентификацию, роли и backend-авторизацию, а не интеграцию стороннего сервиса.

Поэтому ЛР7 была адаптирована так:

- сохранена собственная backend-аутентификация;
- добавлены роли и role-based access;
- добавлены методы управления своим аккаунтом;
- добавлен один admin-only сценарий;
- отражены изменения во frontend, Swagger и тестах.

## 4. Исходное состояние проекта перед ЛР7

До начала ЛР7 в проекте уже были:

- `AuthService`, `AuthController`, `SessionAuthGuard`;
- `GET /api/auth/me`, `POST /api/auth/login`, `POST /api/auth/register`, `POST /api/auth/logout`;
- `UserRole` в `Prisma` со значениями `USER` и `ADMIN`;
- хранение роли в таблице `User`;
- поддержка ролей на frontend через `ProtectedRoute`;
- тестовый admin в seed;
- e2e-инфраструктура и Swagger.

При этом отсутствовали:

- методы изменения профиля и пароля;
- backend-проверка ролей через отдельный guard;
- отдельный admin-модуль;
- полноценный admin-only сценарий;
- документация и автотесты именно под сценарии ЛР7.

## 5. Что было реализовано

## 5.1. Усилено хранение паролей

В `src/auth/auth.service.ts` хранение паролей было переведено с обычного `sha256` на `scrypt`.

Что сделано:

- добавлен новый формат хэширования через `scrypt`;
- при логине поддерживается автоматическое обновление старых `sha256`-хэшей;
- seed также обновлен на новый формат.

Это позволило улучшить ЛР7 без изменения схемы базы данных.

## 5.2. Добавлено управление своей учетной записью

В auth API были добавлены:

- `PATCH /api/auth/profile`
- `PATCH /api/auth/password`

Для этого созданы DTO:

- `src/auth/dto/update-profile.dto.ts`
- `src/auth/dto/change-password.dto.ts`

Пользователь теперь может:

- изменить имя;
- изменить пароль, указав текущий пароль.

## 5.3. Добавлена backend-авторизация по ролям

Для проверки ролей реализованы:

- `src/auth/roles.decorator.ts`
- `src/auth/roles.guard.ts`

Логика:

- `SessionAuthGuard` проверяет наличие сессии;
- `RolesGuard` читает роль пользователя из БД;
- если роль не подходит, backend возвращает `403 Forbidden`.

Это означает, что admin-доступ теперь реально контролируется сервером, а не только frontend.

## 5.4. Реализован AdminModule

Создан отдельный модуль:

- `src/admin/admin.module.ts`
- `src/admin/admin.controller.ts`
- `src/admin/admin.service.ts`

Добавлены endpoint'ы:

- `GET /api/admin/users`
- `PATCH /api/admin/users/:id/role`

Также добавлено ограничение:

- нельзя снять роль у последнего администратора.

## 5.5. Обновлен frontend

Во frontend были добавлены:

- страница `/profile`
- страница `/admin/users`
- новые API-методы для профиля и admin-раздела
- ссылка на admin-раздел только для пользователей с ролью `admin`

Это позволило показать ЛР7 не только на уровне backend, но и на уровне пользовательского интерфейса.

## 5.6. Обновлена документация Swagger

В Swagger были добавлены новые protected endpoint'ы ЛР7:

- profile
- password
- admin users
- change user role

Благодаря этому лабораторную работу можно демонстрировать через `/api/docs`.

## 5.7. Добавлены тесты ЛР7

В `test/app.e2e-spec.ts` добавлены проверки:

- изменение профиля;
- смена пароля;
- запрет admin API для обычного пользователя;
- успешный admin-сценарий списка пользователей;
- успешная смена роли.

## 6. Что не вошло в реализацию

Сознательно не добавлялись:

- `OAuth 2.0`
- `Auth0`, `Firebase Auth`, `SuperTokens`
- social login
- reset password по email
- JWT и refresh tokens
- сложная permission-система поверх каждой сущности

Для проекта `GymHelper` это было бы избыточным.

## 7. Проверка выполнения ЛР7

Успешно проходят команды:

```bash
npm run build
npm test -- --runInBand
npm run test:e2e -- --runInBand
```

Дополнительно можно проверить вручную:

- `/api/docs`
- `/profile`
- `/admin/users`
- login/register/logout

## 8. Итог

По результатам ЛР7 в проекте `GymHelper` реализованы:

- полноценная session-based аутентификация;
- role-based backend-авторизация;
- управление своим профилем и паролем;
- административный сценарий управления пользователями;
- frontend-интерфейс для новых сценариев;
- автотесты и Swagger-документация.

Таким образом, ЛР7 для проекта `GymHelper` можно считать выполненной в адаптированном и практичном объеме: без лишней внешней инфраструктуры, но с полноценной демонстрацией аутентификации, авторизации и ролей.
